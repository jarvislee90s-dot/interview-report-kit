## 3. 阶段① 爬取实录

### 登录态（用户已选定方案）

- 使用 Playwright MCP 管理的自动化浏览器（持久 profile）。实测该 profile 无飞书登录态（访问妙记链接跳转登录页）。
- **用户在该自动化浏览器窗口中登录一次**（扫码或账密）。登录态持久化，本次与后续任务复用。
- 已否决的备选：从 Edge 提取 cookies 注入（browser_cookie3，受新版浏览器加密影响成功率不确定）；computer-use 直接操作用户 Edge（66 分钟虚拟滚动列表提取慢且易漏）。

### 提取方式（两级策略）

1. **首选：内部转录接口重放**。导航到妙记页后用网络请求监听发现文字记录的 XHR 端点，然后以页面自身会话（cookie 自动携带）在页面上下文 fetch 分页拉取全量 JSON（含发言人、时间戳、文本）。
2. **兜底：滚动 + DOM 提取**。模拟滚动文字记录区触发虚拟列表加载，逐屏读取 DOM 中「发言人 + 时间戳 + 文本」节点，按时间戳去重合并。

### 会议实录.md 格式

```markdown
# OceanDemo 路演访谈会议实录

> 来源：飞书妙记 <链接>
> 会议时间：2026-03-10 09:06 · 时长 1:06:24 · 发言人 8 人
> 说明：本文件为自动化爬取的原始实录，未经校对。

---

**发言人姓名** 00:00:01
段落原文……

**发言人姓名** 00:00:33
段落原文……
```

- 每条发言一个块：`**姓名** HH:MM:SS` + 段落（同一条发言内的换行合并为一段）。
- 若接口返回发言人头像/身份信息（如公司），在发言人列表节保留。

## 4. 阶段② ASR 转录（video-summary 技能）

- 技能位置：`E:\LLMproject\VideoSkills\.agents\skills\video-summary`
- 命令：`python .agents/skills/video-summary/scripts/process.py "C:\Users\bunny\Downloads\demo_interview_audio.m4a" --output-dir "<产物目录>\asr_runs" --language zh`
- 环境准备：`pip install faster-whisper`（实测缺失；yt-dlp 缺失但本地文件路径不需要，如脚本 import 报错则一并安装）。
- 脚本行为：ffmpeg 将 m4a 转 16kHz 单声道 wav（`-vn` 对纯音频文件兼容）→ faster-whisper 转录 → `transcript.json`（带时间戳）+ `transcript.txt`。
- 模型：默认 `large-v3-turbo`（faster-whisper 映射）。本机无 NVIDIA GPU，走 CPU int8；66 分钟音频预计 10~30 分钟。模型首次下载约 1.5GB，若 huggingface.co 不可达则设 `HF_ENDPOINT=https://hf-mirror.com` 重试。
- 本阶段**不做总结**（用户明确要求：转录仅用于修正实录）。

## 5. 阶段③ 交叉修正 → 会议实录（修正）.md

修正原则：

1. 逐段对照 ASR 文本与妙记实录。**只修两类问题**：
   - 错别字/同音字/专有名词错误（人名、公司名、债券与航运术语、数字），以 ASR 证据或领域常识为依据；
   - 明显逻辑不通的断句/语序（以 ASR 上下文为参照微调标点与断句）。
2. ASR 与实录一致的内容一律不动；无把握的不改（宁保留原文）。
3. 不改写语言风格、不删减内容、不合并/拆分发言人段落；发言人归属与时间戳保持原位，保证两版可逐段对照。
4. 文件头部附「修正说明」节，列出主要修改点（原文本 → 修正文本 + 依据），便于抽查；用户不需要可自行删除。

产出：`会议实录（修正）.md`，结构与 `会议实录.md` 完全一致。

## 6. 阶段④ 会议总结.md + 思维导图

### 总结（video-summary 摘要方法）

- Agent 读取 `transcript.txt` 与修正版实录，生成 `会议总结.md`：
  - 头部：会议信息（时间、时长、参会方、来源）
  - 正文：按主题分节（二级/三级标题），提取核心观点与关键信息
  - 保留重要细节：数字（金额、规模、年限）、专有名词、关键论据
  - 用列表和引用块突出要点

### 思维导图（video-to-slides 的导图方式，阶段 2 ⑦）

- 基于总结提取核心观点，**手写 Mermaid mindmap** 源文件 `会议总结思维导图.mmd`：根节点 = 会议主题，主分支 = 总结各章节，叶子 = 关键要点（保持层级 ≤ 3，节点文字精炼）。
- 用本机已安装的 `mmdc`（npm 全局，node v25）渲染 PNG。
- 附加方式：`会议总结.md` 尾部依次附 `![思维导图](./会议总结思维导图.png)` 与 ` ```mermaid ` 源码块（支持 mermaid 的查看器可直接渲染）。
- 兜底：mmdc 渲染失败 → 仅嵌 mermaid 源码块，并用 Playwright 打开 mermaid 渲染页截图存 PNG。

## 7. 错误处理

| 风险 | 处置 |
| --- | --- |
| 登录二维码过期/超时 | 刷新登录页重试；等待用户完成登录后再继续 |
| 内部接口无法发现/重放失败 | 切换滚动 + DOM 兜底提取 |
| 虚拟列表滚动漏段 | 以最后时间戳 ≈ 1:06:24 校验，缺段则补滚 |
| faster-whisper 模型下载失败 | 设置 `HF_ENDPOINT=https://hf-mirror.com` 重试 |
| ASR 中途崩溃 | 删残留空文件后重跑（脚本支持断点跳过已完成产物） |
| mmdc 渲染失败 | 兜底方案（见阶段④） |
