# pipeline.md —— LLM 环节操作细则（④⑤⑥⑦ + 质量核对）

适用于 SKILL.md 工作流中由 agent 执行的环节。以下原则源自 2026-03-10 OceanDemo 路演访谈项目的全流程实战验证。

## 1. 校正原则（环节④，最关键）

**总原则：妙记实录质量通常优于本地 whisper。** 妙记是针对会议场景优化的识别引擎，且带发言人分离；本地 faster-whisper 主要用作**旁证**而非替代。因此：

- **只修有两类证据支撑的错误**：
  1. **双源交叉印证**——whisper 同一段识别出了不同的写法，且 whisper 版本更合理（通常是英文术语/专有名词）；
  2. **领域常识**——金融/行业术语的标准写法可以由上下文确定（如上下文在谈浮动利率基准，则 "sofa" 必为 SOFR）。
- **无把握保留原文**。宁漏勿错：错改比漏改危害大（错改会污染下游总结）。
- 禁止"顺手润色"——本环节只做机械字符串替换，语义润色是环节⑤的事；两者混在一起无法审计。

**三类高频错误**（按命中率排序）：

1. **专有名词**：公司/人名/产品名（OceanDemo→OceanDemo、马新基→马士基、杨明→阳明）；
2. **术语同音**：SOFR、unlevered IRR、OPEX、unsecured、P&I、time charter、open book 等；
3. **近音词**：中文人名/机构（洪博→李四）；孤例且无旁证的（如只出现一次的"韩旭"）保留原文或随过渡语整体省略，不硬改。

**规则格式**（`corrections.json`，UTF-8）：

```json
[
  {"old": "OceanDemo",     "new": "OceanDemo",       "expect": 1, "basis": "whisper 同段识别为 OceanDemo；公司官方名称"},
  {"old": "unlevel IR",  "new": "unlevered IRR", "expect": 2, "basis": "上下文为项目内部回报率；金融术语标准写法"},
  {"old": "PII",         "new": "P&I",           "expect": 2, "basis": "船舶保赔险标准险种，与 hull 船壳险并列出现"},
  {"old": "sofa",        "new": "SOFR",          "expect": 3, "basis": "whisper 同段识别为 SOFR curve；美元浮动利率基准"}
]
```

- `expect` 填**实测命中数**——写规则前先数一遍：
  ```bash
  grep -o "sofa" 会议实录.md | wc -l
  ```
- `expect` **必须是整数**（`apply_corrections.py` 拒绝其他类型；缺省为 1）。
- **规则按序应用**：第 i 条在前 i-1 条应用后的文本上计数替换。若两条规则有包含关系（如 `sofa curve` 与 `sofa`），先写长串、后写短串，且短串的 expect 要按扣除长串后的剩余命中数填。
- 任何一条命中数 ≠ expect → **全量拒绝写入**（改 expect 或改 old 后重跑）。
- apply_corrections 的段落数守卫是纯计数（改写时间戳行格式不变不会被拦）——所以 old 串不得包含 `**发言人** 时间戳` 行结构，规则只动正文文本。
- `basis` 必填且要能落地（"whisper 同段识别为 X" / "术语标准写法"），供事后审计（basis 目前无脚本强制，属 agent 自律与审计字段）。

## 2. 润色原则（环节⑤，就地改写 会议实录（修正）.md）

- **合并时间块**：同一发言人**连续**的多段发言合并为一个时间块，时间戳写起止区间：
  ```markdown
  **李四** 00:01:17 – 00:02:43
  ```
  **非连续**多轮（中间被他人打断）合并为一个块时，用 `/` 罗列各时间点：
  ```markdown
  **demo 张三** 01:01:50 / 01:02:30 / 01:02:42
  ```
  （起止用 ` – `，罗列用 ` / `，均为渲染引擎 `ENTRY_RE` 认可的分隔符。）纯寒暄的开场段可归并为一个伪发言人块，如 `**开场交流** 00:00:01 – 00:00:52`。
- **口语书面化，只顺句不改意**：删语气词、复言（"呢/啊/对吧/实事求是地说"）、修顺语序；**不增删事实、不改数字、不换说法**。
- **过渡语省略、插话内嵌**：纯过渡句（"嗯""对对""好的"）直接省略；他人有实质内容的短插话用括号内嵌在相关段落里，如 `（赵六：市场也在下行）`。
- **长块逻辑分段**：一个时间块内多个论点用 `**1）小标题：**` 开头分段，小标题由内容提炼。
- **关键数字与术语加粗**：`**3 月 12 日**`、`**unlevered IRR**`、`**90%**`。
- **按议题分章节**：`## 一、标题（HH:MM:SS – HH:MM:SS）`——章节标题**必须带（时间范围）**且括号内含冒号，渲染引擎据此拆 CHAPTER_TITLE/CHAPTER_TIME；标题序号用 一、二、三。时间范围取该章节首末发言的时间戳。
- **录音模糊标注**：两套识别都无法辨识的片段标 `（录音模糊）`，不猜。
- 头部 meta 行（`> 来源：` `> 会议时间：… · 时长 H:MM:SS · 发言人 N 人` `> 发言人 …：`）保留并更新说明行（apply_corrections 已自动改为"已对照本地音频转录逐段交叉校对"）。

## 3. 总结结构（环节⑥，会议总结.md）

```markdown
# <会议名> 会议总结

> 会议时间：2026-03-10 09:06 · 时长 1:06:24 · 发言人 8 人
> 参会方：<甲方（分部门列人名）；乙方（人名）>
> 议题：<一句话>
> 来源：飞书妙记实录（经本地音频 faster-whisper 转录交叉校对）
> 说明：<免责/口径说明，如"个别片段两套语音识别均无法辨识（已在实录中标注）">

注意：总结 md **不要**在文末附思维导图（图片链接/mermaid 源码都不写）——导图由环节⑦的 .mmd 渲染成 PNG 后经 `render.py --mindmap` 注入模板；渲染器虽会自动剥离"## 附：思维导图"附录，但源头不写才是正解。

---

## 一、会议概览

<一段话：会议性质 + 双方各做了什么 + 覆盖了哪些主题>

## 二、<主题一>（<所属方>）

- **要点标签**：内容……关键数字加粗，如 **3 月 12 日**、**2.15%**。
- **要点标签**：……

## 三、<主题二>
…

## N、要点与后续跟进

- <行动项 / 待核对事项 / 结语义>

> <一句点睛的原话>。—— <发言人>
```

- **首行 `# 标题` 由渲染承接**（模板取其作 TITLE，正文 h1 自动隐藏）；正文分节一律用 `##`。
- 要点用 `- ` 列表，**关键数字加粗**；每节要点先给结论性标签再展开。
- 每节可附 1 条引用块（`> `）放点睛原话，注明发言人。
- 末节"要点与后续跟进"固定存在：行动项、待核对事项（翻译口径/模糊片段）、结语义。
- 不要在总结 md 里嵌思维导图图片/源码——思维导图经 ⑦ 的 png 由 `--mindmap` 注入。

## 4. 思维导图（环节⑦）

- mermaid **mindmap** 语法；`root((主题))`；主分支 = 总结的 `##` 章节；**层级 ≤3**（root → 主分支 → 叶节点）；**节点 ≤15 字**（数字尽量保留，如 `26至29年几乎无到期`）。
- 推荐加 tidy-tree 布局头：
  ```text
  ---
  config:
    layout: tidy-tree
  ---

  mindmap
    root((OceanDemo路演访谈))
      1. 发行安排
        9月17日发行
        9月10日前出推荐函
      2. 业务模式
        全球最大独立集装箱船东
        平均11年死价租约
  ```
- 渲染：
  ```bash
  mmdc -i 思维导图.mmd -o 思维导图.png -w 1600 -b white
  ```
- **失败兜底**：mmdc 装不上/渲染报错时，⑧ 不传 `--mindmap`（模板 `IF:MINDMAP` 块自动隐藏，页面不留空洞），并把 mermaid 源码以代码块附在 `会议总结.md` 末尾备查（仅嵌源码）。

## 5. 质量核对清单（⑧ 之前逐项过）

1. **关键数字逐项核对**：从 `会议总结.md` 提取所有数字（含百分比、金额、日期、船数、年限），逐一在润色版实录中验证存在：
   ```bash
   grep -o "2\.38%" 会议总结.md | wc -l      # 总结里出现了几次
   grep -c "2\.38%" 会议实录（修正）.md       # 实录里是否存在
   ```
   总结中的任何数字若在实录中 grep 不到，要么是实录遗漏（回④⑤补）、要么是总结写错（改总结）——不允许无出处的数字。口径换算过的数字（如"约 1/4"）需能在实录找到原话。
2. **发言人归属不变**：抽查每个章节的 `**发言人**` 块——润色只允许合并不允许改说话人；比对方法是同一时间戳附近的发言人在原始 `会议实录.md` 与润色版中一致。
3. **时间戳不丢**：润色版每个时间块至少保留一个原始时间戳（起止区间的起点必须是原始段落的真实时间戳，不得推算）；总时间覆盖从 00:0x 到末段，末块时间戳 ≈ 会议实录.md 的末段时间戳。
4. corrections.json 全部通过（`✅ applied N 条`），无残留 ❌；润色版头部说明行已变为"已对照本地音频转录逐段交叉校对"。

## 6. 快速总结原则（仅录音 · 单产物线）

- 输入只有 `transcript.txt`（无发言人归属、无时间戳结构）——总结**不按发言人组织**，按主题分节；引用原话不标注发言人（可写"主讲人/与会者"）。
- 头部 meta：`> 来源：本地录音 faster-whisper 转录（快速模式，未经发言人区分）`；说明行注明"转写未经发言人区分与逐段校对"。
- 质量纪律不变：关键数字须能在 transcript.txt 中 grep 到出处；听不清的片段标（录音模糊），不猜。
- 思维导图默认生成（§4 原则照用）。

## 7. 对话式标记发言人（③′ 之后、② 落名）

- 提问给足辨识信息：每号 spk 的首/中/末样例句 + 段数占比；用户不确定的标签**不要硬映射**，保留 `spk:N` 原名。
- `--rename` 只做名字替换，不改段落归属；同一人被拆成两号（分离误差）不在此环节处理——如实保留，可提示用户"X 号与 Y 号疑似同人，⑤ 润色时可合并其发言块"。
- 落名后头部来源为"本地录音（FunASR 分离转录）"；说明行写"转写经 FunASR 说话人分离，发言人名为人工标记"。
